# 称呼计算器

根据用户的亲戚关系陈述，计算出正确的亲属称呼。

## 适用场景

当用户询问“我应该叫他/她什么”时，或处理涉及多代、旁系、姻亲等复杂亲戚关系描述时，加载此技能。

## 核心规则

- **规则1：解析关系链**。将用户的输入（如“他的爸爸的妈妈”）解析为一条从“他/对方”到“我/自己”的单向关系链。
- **规则2：计算辈分差**。计算关系链中的代际数量，确定双方的辈分高低。
    - “爸爸的妈妈”表示对方比我高两代。
    - “我的儿子的儿子”表示对方比我低两代。
    - 相同代际（如“我的兄弟”）表示平辈。
- **规则3：确定关系类型**。
    - **直系**：关系链中只涉及父/母、子/女（如“他的爸爸”）。
    - **旁系**：关系链中包含兄弟姐妹（如“他的爸爸的兄弟”）。
    - **父系/母系**：通过关系链中第一个环节（对方上溯的第一人）是“爸爸”还是“妈妈”分支来判断。
    - **姻亲**：关系链中包含“配偶”或“丈夫/妻子”等。
- **规则4：生成称呼**。根据辈分差、关系类型（直系/旁系）、分支（父系/母系）、性别，匹配标准称呼。
    - **平辈旁系**：
        - 父系：比自己大叫“堂哥/姐”，比自己小叫“堂弟/妹”。
        - 母系：比自己大叫“表哥/姐”，比自己小叫“表弟/妹”。
    - **长辈旁系**：父系男性为“伯/叔”，女性为“姑”；母系男性为“舅”，女性为“姨”。
    - **晚辈旁系**：统称为“侄子/侄女”或“外甥/外甥女”（需结合具体分支）。
    - **直系**：使用标准直系称呼（如爷爷、孙子、叔叔等）。
- **规则5：处理模糊信息**。如果用户陈述中缺失判断所需的关键信息（如无法判断“兄弟”是堂是表，或无法确定性别），必须直接询问用户以补全信息，不能自行猜测。
- **规则6：验证共同祖先**。对于表/堂兄弟姐妹等称呼，需确保双方最终能追溯到共同的直系祖先（如共同的祖父母/外祖父母）。

## 示例

**示例1：计算表/堂兄弟姐妹**
- 用户输入：“他的爸爸的妈妈是我的妈妈的妈妈，我叫他什么？”
- 规则应用：
    1. 关系链（从对方到我）：他的爸爸 -> 他的妈妈 -> 我的妈妈 -> 我的妈妈的妈妈（即我外祖母）。对方的妈妈是我外祖母，即**对方是我舅舅的孩子**。
    2. 辈分差：0（平辈）。
    3. 关系类型：旁系。共同祖先为“外祖父母”。分支：对方通过其爸爸（我的舅舅）连接，属于母系旁系。
- 计算结果：母系旁系平辈。比自己大叫“表哥/姐”，比自己小叫“表弟/妹”。**需询问对方性别**。

**示例2：计算叔伯/姑舅**
- 用户输入：“他是我爸爸的哥哥，我叫他什么？”
- 规则应用：
    1. 关系链：他是我爸爸的哥哥。
    2. 辈分差：+1（长我一辈）。
    3. 关系类型：父系旁系。
- 计算结果：父系旁系长辈。**为“伯父”**。

**示例3：信息不足**
- 用户输入：“我表哥的孩子是我的什么？”
- 规则应用：
    1. 关系链：我表哥 -> 我表哥的孩子 -> 我。我是他孩子的表叔/姑。
    2. 辈分差：-1（晚一辈）。
    3. 关系类型：表亲的子女。
- 计算结果：根据传统习惯，通常称呼为“表侄/表侄女”，但需明确对方性别。

## 禁止事项

- 禁止忽略代际差异，直接将所有非直系亲属统称为“亲戚”或“哥哥姐姐”。
- 禁止在关系链解析错误时仍给出答案。必须重新计算。
- 禁止使用方言或口语化称呼（如“堂客”、“嬢嬢”），必须使用标准中文亲属称谓。
- 禁止在无法确定对方性别或关系链中存在歧义（如“兄弟”是堂是表）时，自行假设并给出单一答案。必须询问澄清。
- 禁止给出“这个要看你们家习惯”等推诿性回答。在遵循核心规则的前提下，应给出最符合通用习惯的标准称呼。
